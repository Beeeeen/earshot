# Earshot — 規格

**一句話：** 語音是廣播媒介。Earshot 是一個給 Alexa+ 的照護協調 MCP server，
它把「房間」當成不可信通道——**受保護的值永遠不會被唸出來**，但問題仍然被回答。

## 為什麼是語音，而不是別的

現有所有隱私模型都假設有一塊私人螢幕。語音沒有。
奶奶客廳裡的 Echo，聽得到的人包括她女兒、居家照服員、鄰居、水電工。

「Alexa，媽今天吃藥了嗎？」
- 拒答 → 沒用。
- 唸出「她早上八點吃了 40mg Furosemide，治療充血性心衰竭」→ 在訪客面前洩漏病史。

Earshot 的第三條路：**如實回答，但把敏感的部分換一條通道送。**
語音說「吃了，準時。有一件事要你看一下，已經傳到你手機。」
細節出現在提問者自己已連結的裝置上（MCP Apps 卡片 / 推播）。

## 核心不變式（可被機器檢查）

> **受保護的值，永遠不會出現在任何 tool 的 spoken 回傳字串裡。**

不做房間感測、不要求使用者宣告誰在場、不猜。假設永遠有人在聽，因為家裡永遠有人在聽。
這比偵測更強，也更誠實——我們沒有能力偵測，就不假裝有。

例外只有一個：使用者主動說「我一個人」開啟的 solo window，有效期 5 分鐘、
單一裝置、單一提問者，過期自動關，且每次動用都記進 ledger。

## 分級（沿用但重新定義）

| 級別 | 例子 | 語音可否 |
|---|---|---|
| `spoken` | 有沒有吃藥、準不準時、下次幾點 | ✅ 可唸 |
| `private` | 藥名、劑量、診斷、醫師姓名、檢驗數值 | ❌ 只能走私人通道 |
| `sealed` | 完整病歷、保險號、地址 | ❌ 連私人通道都不給，只給「在 App 裡看」 |

分級是**資料的屬性**，不是回答時才判斷。tool 的回傳型別在編譯期就分成
`spoken: string`（會被唸）與 `private: object`（不會被唸），
**兩者在型別上不可互換**。洩漏要在「表達不出來」的層次被擋掉，而不是事後過濾。
（這條沿用 Blindfold 學到的：事後檢查是劇場。）

## 身分

只信 OAuth 2.1 + PKCE 換來的 access token。每個家庭成員各自 link 自己的帳號，
token 決定他是誰、能看什麼。**不使用聲紋、不使用 device id 推斷身分**——
文件沒有保證會傳這些，我們就不依賴。

授權是明確的 grant table：誰對誰的哪一級資料有權限，由被照護者或其代理人設定。

## 硬性技術約束（來自 Alexa+ 文件）

- MCP spec **2025-11-25**，Streamable HTTP
- OAuth 2.1 + PKCE (S256)
- **round-trip < 500ms** ← 這是硬上限，不是目標。所有 tool 都要在預算內
- 公開 HTTPS URL

## Tools（草案）

| Tool | 回傳 | 說明 |
|---|---|---|
| `check_adherence` | spoken + private | 今天/本週吃藥狀況。spoken 只有「有/沒有/幾點」 |
| `next_dose` | spoken | 下一次該吃的時間。時間本身不敏感 |
| `log_dose` | spoken | 記錄已服用 |
| `report_symptom` | spoken + private | 記錄症狀，通知有權限的人 |
| `care_summary` | private only | 給有權限者的完整摘要，走私人通道 |
| `who_can_see` | spoken | 說出目前誰對這位被照護者有權限——這件事應該可以大聲講 |
| `open_solo_window` | spoken | 使用者宣告獨處，5 分鐘 |
| `disclosure_ledger` | spoken + private | 什麼被說出口過、什麼走了私人通道 |

## Demo 的爆點

agent 被**要求**唸出藥名，而它在結構上做不到——但它沒有失敗，
它做了更好的事：把細節送到你手機，語音只說「傳過去了」。

## 評分對照（四項等權重）

- **Tech Implementation** — 真 MCP 2025-11-25 / Streamable HTTP / OAuth 2.1 PKCE /
  全 tool < 500ms（實測數字進 README）/ MCP Apps 卡片
- **Design** — 為聽不清楚、看不到螢幕的人設計的語音流程；每句話都短
- **Potential Impact** — 高齡照護 + 共享裝置，是 Alexa+ 真實的產品問題
- **Quality of Idea** — 「房間就是洩漏管道」這個框架，語音獨有

## 不做什麼（誠實邊界，要寫進 README）

- 不做聲紋辨識——平台沒保證給，我們不假裝
- 不能防止有人偷看你的手機
- 不是 HIPAA 合規產品
- solo window 靠使用者誠實宣告，我們無法驗證他是不是真的一個人
